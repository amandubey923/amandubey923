## Build approach

I prefer a product loop that keeps engineering decisions close to real use:

```text
Understand the user → design the smallest useful flow → build the system → test the edges → ship, observe, improve
```

- Start with a concrete problem and a small, clear interface.
- Build for maintainability: readable components, typed boundaries, and deliberate data flow.
- Use implementation as a learning tool—especially for algorithms, UI motion, and full-stack architecture.
